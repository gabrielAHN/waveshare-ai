# Home Assistant setup

This guide installs Sensor without Hermes. If both plugins resolve the same OIDC issuer, public
client, RFC 8628 endpoints and Host header, one phone approval and sign-out covers both. Permissions
do not merge: Home Assistant checks `providers.home_assistant.sign_in.groups`, so a Hermes-only
account cannot read sensors.

Commands run from the repository root on the gateway host. First complete the
[base-device setup](../../devices/waveshare-esp32-s3-touch-amoled-1-8-v2/README.md#install) with
`WAVESHARE_AI_PROVIDERS=home_assistant`.

## Requirements

- Python 3.11+, `openssl`, a reachable RFC1918 LAN address, and the `waveshare-bridge` package.
- An OIDC provider supporting client credentials, RFC 8628 device authorization, explicit consent,
  and groups plus a display name from userinfo. The example was tested with exactly Authelia 4.39.28.
- A bearer-only auth proxy on `https://ha.example.com/api/waveshare-sensors`.
- Home Assistant sensor entities for temperature (°C), humidity (%RH), pressure (hPa), and PM1,
  PM2.5 and PM10 (µg/m³). Configure availability so a silent source becomes `unavailable`; for an
  MQTT sensor, use `expire_after`.

The gateway host owns the Home Assistant API token. Never put it in `bridge.json`, the board,
tracked examples, command arguments or logs.

## 1. Register phone approval and machine access

Merge these entries into your Authelia configuration. They are separate clients: the public client
approves a person and the confidential client authorizes only the sensor route.

### Public phone client

```yaml
identity_providers:
  oidc:
    authorization_policies:
      waveshare_pairing:
        default_policy: deny
        rules:
          - {policy: two_factor, subject: 'group:admins'}
    lifespans:
      custom:
        waveshare_pairing: {access_token: 5m, id_token: 5m}
    clients:
      - client_id: waveshare-pairing
        client_name: Waveshare AI phone approval
        public: true
        authorization_policy: waveshare_pairing
        lifespan: waveshare_pairing
        consent_mode: explicit
        scopes: [openid, profile, groups]
        grant_types: ['urn:ietf:params:oauth:grant-type:device_code']
        response_types: []
        token_endpoint_auth_method: none
```

Userinfo must return `groups` and `preferred_username` or `name`. Use the same exact public client
for Hermes when you want one shared phone approval; keep each provider's `groups` list distinct.

### Machine client and exact-path proxy rule

```yaml
server:
  endpoints:
    authz:
      forward-auth-bearer:
        implementation: ForwardAuth
        authn_strategies:
          - name: HeaderAuthorization
            schemes: [Bearer]

access_control:
  rules:
    - domain: [ha.example.com]
      resources: ['^/api/waveshare-sensors$']
      subject: ['oauth2:client:waveshare-home']
      policy: one_factor
    - domain: [ha.example.com]
      resources: ['^/api/waveshare-sensors$']
      policy: deny

identity_providers:
  oidc:
    lifespans:
      custom:
        waveshare_home: {access_token: '1h'}
    clients:
      - client_id: waveshare-home
        client_name: Waveshare AI sensor reader
        client_secret: '$pbkdf2-sha512$...' # hash generated by Authelia
        public: false
        authorization_policy: one_factor
        lifespan: waveshare_home
        audience: ['https://ha.example.com/api/waveshare-sensors']
        scopes: [authelia.bearer.authz]
        grant_types: [client_credentials]
        response_types: []
        token_endpoint_auth_method: client_secret_basic
        access_token_signed_response_alg: none
```

Put these exact-path rules before broader site rules. Attach your proxy's forward-auth middleware
to only `Host(ha.example.com) && Path(/api/waveshare-sensors)`, using Authelia's
`/api/authz/forward-auth-bearer` endpoint. Preserve the request bearer for validation, do not accept
portal cookies, and do not redirect unauthenticated requests to login. Forward an allowed request
to the loopback sensor adapter from the next step. The machine-client rule depends on the
ClientID-aware authorization fix verified in the exact tested Authelia 4.39.28; configuration
validation alone does not prove that a wrong client is denied.

Validate the complete Authelia configuration before restarting it. Keep the generated plaintext
machine secret for `home-client.json`; only its hash belongs in Authelia.

## 2. Run the gateway-owned sensor adapter

[The example adapter](../../bridge/examples/home-assistant-sensor-adapter.py) listens only on
`127.0.0.1:8099`, reads the six configured entities through Home Assistant's state API, and emits
the bridge JSON contract. Install it with a service manager and provide these environment variables
through a private service environment file:

```dotenv
HOME_ASSISTANT_URL=https://home-assistant.example.com
HOME_ASSISTANT_TOKEN=REPLACE-WITH-A-LONG-LIVED-API-TOKEN
SENSOR_TEMPERATURE=sensor.room_temperature
SENSOR_HUMIDITY=sensor.room_humidity
SENSOR_PRESSURE=sensor.room_pressure
SENSOR_PM1=sensor.room_pm1
SENSOR_PM25=sensor.room_pm25
SENSOR_PM10=sensor.room_pm10
```

Start it from the repository checkout:

```sh
python3 bridge/examples/home-assistant-sensor-adapter.py
```

The auth proxy, not the bridge, reaches `http://127.0.0.1:8099/api/waveshare-sensors`. The adapter
uses the private Home Assistant token only in its downstream `Authorization` header. A successful
response matches [sensor-endpoint.example.json](../../bridge/examples/sensor-endpoint.example.json):

```json
{
  "now": 1790000000,
  "sensors": {
    "temperature": {"state": "22.4"},
    "humidity": {"state": "48.0"},
    "pressure": {"state": "1013.2"},
    "pm1": {"state": "2"},
    "pm25": {"state": "4"},
    "pm10": {"state": "unavailable"}
  }
}
```

`now` is integer epoch seconds. States are strings. Missing, `unknown`, `unavailable` or nonnumeric
states display `--`. Home Assistant availability, rather than `last_updated`, determines freshness:
a valid steady reading can keep the same timestamp.

## 3. Install and configure the bridge

Install the package without installing the Hermes plugin:

```sh
python3 -m venv ~/.local/share/waveshare-bridge/venv
~/.local/share/waveshare-bridge/venv/bin/pip install -e ./bridge
export PATH="$HOME/.local/share/waveshare-bridge/venv/bin:$PATH"
waveshare-bridge init --provider home_assistant
```

The initializer asks for bridge networking/name, the machine token endpoint/client/scope/secret,
resource URL/audience and the public phone client. It does not ask for a Hermes dashboard or create
Hermes credentials. It creates private `bridge.json` and `home-client.json`, board identity and TLS.
For non-default issuer paths or groups, edit the generated `bridge.json`; `providers` remains Home
Assistant only:

```json
{
  "bind": "10.0.0.10",
  "port": 8098,
  "name": "Waveshare AI bridge",
  "mdns": true,
  "allow_ip": null,
  "providers": {
    "home_assistant": {
      "client_file": "home-client.json",
      "sign_in": {
        "issuer": "https://auth.example.com",
        "client_id": "waveshare-pairing",
        "groups": ["admins"],
        "oidc_paths": {
          "device_authorization": "/api/oidc/device-authorization",
          "token": "/api/oidc/token",
          "userinfo": "/api/oidc/userinfo"
        }
      }
    }
  }
}
```

Use the gateway's published issuer. `host_header` is available for explicit host routing;
`client_file` inside `sign_in` can select a different file when phone approval and machine access
use different issuers. Providers share a phone flow only when issuer, public client id, all three
paths and Host header resolve identically.

Write `home-client.json` with mode 0600:

```json
{
  "token_endpoint": "https://auth.example.com/api/oidc/token",
  "client_id": "waveshare-home",
  "client_secret": "REPLACE-WITH-THE-PRIVATE-PLAINTEXT-SECRET",
  "scope": "authelia.bearer.authz",
  "audience": "https://ha.example.com/api/waveshare-sensors",
  "resource_url": "https://ha.example.com/api/waveshare-sensors"
}
```

The scope accepts 1–8 provider-specific tokens but rejects `openid`, `offline_access` and
`hermes.*`. URLs must use HTTPS without credentials, query or fragment; loopback HTTP is supported
only for `127.0.0.1`. Optional `token_host_header` and `resource_host_header` support explicit
routing. `ca_file` affects only the machine token endpoint TLS; the resource URL uses system CA trust.

Run the bridge in the foreground or install it under your service manager:

```sh
waveshare-bridge run
```

`WAVESHARE_AI_CONFIG` or global `--config-dir DIR` selects a different private configuration.

## 4. Enroll and approve the board

1. Run `waveshare-bridge enroll` on the host.
2. Open the board's Home Assistant account tab, select the bridge, and compare the six-digit code
   on both screens. Approve only an exact match.
3. Select **Phone sign-in**, scan the QR, complete 2FA and explicit consent, and confirm the account
   belongs to a Home Assistant group.

`waveshare-bridge boards` lists enrollments; `boards --remove ID` revokes a board and
`boards --revoke-phone ID` clears phone approval. Phone approval is durable local state, not
continuous userinfo polling. Group membership is captured at approval time; approve again after group changes.

## 5. Verify

- `waveshare-bridge status` and `provider list` show only Home Assistant and Sensor.
- A request to the public sensor URL without a bearer, with the wrong client, scope or audience, or
  with an expired token is denied by the proxy without reaching the adapter.
- A signed-out or disallowed board receives `409 home_auth`; an allowed board receives a 48-byte
  WHS1 frame and plausible values. The bridge polls every 10 seconds while Sensor is open and caches
  upstream data for 5 seconds.
- The board and bridge contain no Home Assistant API token. A renderer image does not prove a live
  endpoint or physical device behavior.

| Symptom | Check |
|---|---|
| Tile absent | firmware built with Home Assistant and bridge provider present |
| Phone portal unavailable | public client, device/token/userinfo paths and HTTPS verification host |
| Not for this account | account belongs to a Home Assistant group; approve again after changes |
| Sensor request refused | machine client, exact scope/audience/path and bearer-only proxy order |
| `--` | entity exists, units are correct, and Home Assistant reports it available |
| No readings | adapter service, private token, resource URL and JSON shape |
